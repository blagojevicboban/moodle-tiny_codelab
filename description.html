CodeLab: Runnable Program Examples in the VS Code Editor

Insert program examples in C, C++, Python, Java, C#, JavaScript, Pascal and PHP into any Moodle text, write them in the code editor of VS Code and run them on a Jobe server, on the CodeLab runner or in the browser.

Live demo: try the CodeLab plugins on codelab.tsp.edu.rs. Look around as a guest (Python runs in the browser), or use the demo accounts teacher and student (password Demo-2026) to run every language, the debugger and SQL. Everything is reset every night.

What's New in v1.23.0

  • C and C++ compiler and standard selection: choose GCC, Clang or MSVC compatibility mode (with Visual Studio headers and safe I/O helpers) and pick a C or C++ language standard per example or as the site default.
  • Safe mode (ASan/UBSan) and heap leak detection: catches out-of-bounds access, null pointers, integer overflow and unfreed heap blocks in C and C++, highlighting the line in the editor and unfreed blocks in the Memory view in all 15 languages.
  • Instant compiler error explanations: recognizes 40 common GCC and Clang compiler and linker error messages and shows beginner-friendly explanations with short examples directly under the compiler output in all 15 languages.
  • Multi-file editor tabs and compilation: companion source, header and data files open as keyboard-accessible tabs above the Monaco editor with syntax highlighting by file extension, and extra C/C++/Java/C# source files compile and link together.
  • Peak memory forwarding: passes peak memory reported by CodeLab runner 0.13.0+ to test results.

Core features

  • The code editor of VS Code: Monaco, with syntax highlighting, line numbers, bracket matching, search and multi-file tabs.
  • Typing help and error explanations: typing help for every language (Jedi for Python, snippets and library functions for others), plus instant explanations for 40 common GCC/Clang errors and optional AI explanations through Moodle's AI subsystem.
  • Run on Jobe or the CodeLab runner: choose the server for running and grading, with GCC, Clang or MSVC compatibility mode for C/C++, rate and size limits per user, and a server test page.
  • Interactive runs: with the CodeLab runner, programs ask for their input while they run, as in a terminal, with optional Safe mode (ASan/UBSan) for C and C++.
  • Python in the browser: with Pyodide, input asks for the input while the program runs. Step goes line by line with the variables, Stop also ends an endless loop, and turtle graphics draw under the console.
  • Debugger: breakpoints, Step over and out, call stack and call tree, step back and a timeline, for Python and C/C++.
  • Memory view: frames and the objects their variables point to, with arrows; C and C++ pointers down a linked list to NULL, plus heap leak warnings when allocated blocks are not freed.
  • Complexity: a Python example runs for sizes n from 10 to 500, its steps are drawn beside n, n log n and n², and the growth is named.
  • Flowchart bridge: with the Algorithm plugins, Python examples are drawn as flowcharts, and a flowchart opens as a CodeLab example.
  • VS Code themes and phones: Light, Dark and High Contrast with Auto dark mode; a check button sends input on phones.
  • Simple markup: an example is a pre element with class names, default input and companion files, which survive Moodle's HTML cleaning.

The CodeLab plugins

  • CodeLab for TinyMCE (this plugin): inserts examples in the TinyMCE editor. The other two plugins use its editor and runner.
  • CodeLab filter: turns examples into code editors that readers can edit and run.
  • CodeLab question type: programming questions graded with tests on Jobe or the CodeLab runner.

Requirements

  • Moodle: 4.5 LTS to 5.3 (PHP as required by your Moodle version).
  • A server for running programs: a Jobe server, or the CodeLab runner on your own server (open source, github.com/blagojevicboban/codelab-runner). Python in the browser works without a server.
  • Hosted runner (optional): a paid plan with a monthly quota of runs, provided by the author, Boban Blagojević. Ask for a connection key at boban.blagojevic@tsp.edu.rs. Nothing requires it: Jobe, your own runner and Python in the browser work without it.
  • Python in the browser: Chrome or Edge 137 or newer. Other browsers run Python on Jobe.
  • CodeLab filter: install it too and switch the filter On in Site administration, Plugins, Filters, Manage filters. Without it readers see the examples as plain code.

Privacy

Programs and their input are sent to the server set by the administrator (Jobe or the CodeLab runner, own or hosted) to be compiled and run. Interactive runs, the debugger and SQL always go to the CodeLab runner, with a short-lived signed token that holds only the numeric user id; the runner keeps nothing after the session ends. Nothing is stored in Moodle. When Python runs in the browser, the browser downloads Pyodide from the address in the settings, by default the jsDelivr CDN. It does not send the program or its input there. When the administrator turns on AI explanations, the program and the messages of the console are sent to the AI provider of the site through the AI subsystem of Moodle. The plugin implements the Moodle Privacy API.
